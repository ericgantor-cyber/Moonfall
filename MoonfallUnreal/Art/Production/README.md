# Moonfall UE5 production art

This is the first original, standalone UV-mapped mesh pack, not a claim of AAA fidelity. The six OBJ source assets have explicit triangle budgets and material slots; the geometry is authored by procedural profile construction, not a hand-sculpted high-poly character. No existing content, Z, or Nyra artwork is replaced.

## Import
Open **MoonfallUnreal/MoonfallUnreal.uproject** in Unreal Engine 5.4 with editor scripting enabled, then run **Content/Python/import_production_art.py** via Execute Python Script. It only imports the six allowlisted meshes into /Game/MoonfallProduction/Meshes. Existing assets are skipped. No gameplay collision is generated. The script checks returned assets are StaticMesh objects. Verify axis orientation, scale, normals, UV seams, material slots, appearance and collision separately in the editor. The UVs are per-shell and need proper unique layout before baked texture production. The MTL contains diffuse/specular placeholders, not PBR texture maps. Commit reviewed Unreal packages through the native asset workflow. The native ground-loot display now optionally discovers the sword, cuirass and amulet packages during construction, uses their valid mesh bounds to fit the existing display footprint, and falls back to primitive artwork when packages are absent or invalid. Restart the editor after importing to rebuild native class defaults; confirm the three packages are cooked by adding /Game/MoonfallProduction/Meshes to the editor packaging settings if needed. Check the cooked Windows build, material assignments, orientation, rarity cues and pickup behavior. The Lunar Reliquary optionally replaces shrine base/beacon visuals without altering checkpoint state or discovery. The Gothic Column optionally replaces tall decorative sanctuary pillars in a separate noncolliding instance batch, preserving their original footprints and cube fallbacks. The Firstlight Shield optionally appears on eight sanctuary pillars as display-only heraldry. Inspect the imported shrine and column orientation, materials and bounds in the native editor before shipping. No imported packages or native editor verification are included in this branch.

## Material installation
After importing the six meshes, execute **Content/Python/install_production_materials.py** in UE5. It validates source material slots, creates five physically based constant materials (bronze, leather, steel, stone, moonstone) in /Game/MoonfallProduction/Materials, and fills only default or empty material slots. Existing authored materials and packages are not overwritten. These are base-color, metallic and roughness values, not detailed PBR texture maps. Native material compilation, slot mapping and visual inspection are still required.

## Texture source generation
Run `python MoonfallUnreal/Art/Production/generate_texture_maps.py` from the repository root. It generates 15 deterministic 1024x1024 PNG maps in Art/Production/Textures: five surfaces, each with sRGB base color, tangent-space normal, and linear packed ambient occlusion/roughness/metallic (R/G/B). Existing differing files are never overwritten. These are original procedural tileable textures, not scanned or hand-painted assets. Use a separate output folder for alternative resolutions. Run **Content/Python/import_production_textures.py** in UE5 to import the files into /Game/MoonfallProduction/Textures. Existing texture packages are preserved. The material installer now connects all five PBR channels using three texture samples per material. All fifteen texture packages must exist with appropriate color space and compression; a partial texture set fails before any mesh slot changes. If no texture packages exist, the constant materials remain available. With a complete pack, rerun install_production_materials.py to create separate _Textured materials and upgrade default slots or exact prior constant-material references. Existing custom slots and material packages are preserved. Visual review and native compilation are still pending. CI generates and decodes 64-pixel test maps; the full 1024 source files are generated locally, not committed binary assets.

## Cinematic lighting
The four existing graphics quality levels now scale bloom while keeping motion blur, depth of field, chromatic aberration and lens flares disabled for readability. The remaining engine scalability groups are unchanged. In the isolated Northern Expanse preview, optionally run Tools/install_cinematic_preview_lighting.py to place an unsaved postprocess volume requesting Lumen GI and reflections. This does not modify the campaign, existing hero artwork, project renderer defaults or maps on disk. Validate Lumen support, mesh distance fields, shader compilation, lighting/exposure and low-quality fallback on the target UE5.4 Windows system before saving. No forced Nanite conversion, hardware ray tracing or measured FPS guarantee is included.

## Nanite comparison
Run Tools/create_nanite_benchmark_assets.py inside UE5.4 after importing the production meshes. It creates two separate opt-in benchmark copies in /Game/MoonfallProduction/NanitePreview, never overwriting existing assets. Both preserve full source triangle budgets in their fallback meshes. The original column and reliquary runtime references remain unchanged. These simple meshes are pilot test assets, not evidence that Nanite improves performance. Compare identical instance counts, camera paths, quality settings and resolution, recording GPU frame time, VRAM and fallback appearance before adopting Nanite for detailed environments.

## Firstlight Warden skeletal pilot
The standalone Rigs/SK_MF_FirstlightWarden.gltf contains a 17-joint hierarchy, inverse bind matrices, rigid per-part skin weights, 948 vertices, 1,296 triangles, three material slots and five original keyframed clips (Idle, Walk, Attack, Guard, HitReact). It is an articulated armor prototype, not a high-detail sculpt or a finished deforming character. Open in Blender to review geometry, shoulder and leg pivots, animation pose transitions and orientation; export a reviewed skeletal FBX with mesh/armature and baked actions for UE5.4 import into a separate /Game/MoonfallProduction/Rigs folder. Review the skeleton, clips, materials, collision independence and retargeting before assigning it to any ordinary enemy. No original heroes, divine bosses, runtime enemy collision or combat timing are changed. Blender conversion and Unreal import have not been run.

## PC audit
The full-size Options panel displays cached RAM and logical CPU thread count. For more detail, execute `MoonfallUnreal/Build/Get-MoonfallPCAudit.ps1` in Windows PowerShell. The script prints local JSON with OS version, CPU, visible RAM, graphics adapters, driver versions and conservative starting settings. It does not run a benchmark, change settings, identify the active rendering adapter, test DX12 capability, infer dedicated VRAM from truncated WMI fields, collect personal identifiers or transmit the report. FPS and advanced rendering capability require native verification.

### Live gameplay timing
The local player collects wall-clock intervals between gameplay ticks, excluding menus, defeat, paused gameplay and gaps longer than two seconds. A fixed 240-sample ring publishes average FPS, mean/p95/worst frame interval, slow frames and hitches (100 ms or greater) at most once per accumulated second after 30 samples. Full-size options show the recent gameplay FPS, p95 and hitch count with conservative advice; graphics changes reset the sample. This is CPU-side gameplay interval timing, not GPU timing, a renderer benchmark, or a guarantee of displayed FPS. No automatic settings changes, network transmission or additional ticking actor. Native verification must confirm layout and performance.

The full-size Options panel also reports the current Unreal RHI adapter name and backend (rather than assuming the first Windows-enumerated GPU is active). The name is bounded for the header and missing values appear as unknown. This is renderer identification, not a proof of GPU feature support, dedicated VRAM, or GPU timings. The current gameplay diagnostics include average FPS, 1% low FPS and stutter-aware suggestions.

The PC audit now caches the RHI's dedicated-video-memory capacity and reported texture allocation/pool size on Options entry. The HUD displays capacity in GiB when positive, otherwise unknown. Texture allocation and texture pool are separate cached fields, not total GPU memory usage. No renderer memory query runs from the HUD drawing loop. Native UE5.4 compilation and actual adapter testing remain required.

## Local bug reports
Open Options and click REPORT, press F8, or press the controller right stick (R3). Each explicit action creates a unique JSON diagnostic report under the Unreal project's Saved/BugReports directory, with a five-second rate limit. The button shows REPORT SAVED or SAVE FAILED. Reports contain the engine version, UTC timestamp, active adapter/backend, memory readings, current resolution/quality/reduced-motion setting and available recent gameplay timing estimates. They do not read raw logs, saves, personal files, account names or credentials, and never upload automatically. A tester can review the JSON and attach it manually to a bug report with reproduction steps. This is not a crash-dump collector; it requires the game to be responsive. Existing opt-in Build Center test-summary upload is unchanged. Native validation is required for the keyboard, pointer, controller and file-writing paths.

### Interrupted-session recovery
During normal local gameplay (not editor PIE or dedicated server), the pawn attempts a small recovery snapshot after ten seconds, then at most once per minute. It stores only timestamp, engine version, available gameplay frame metrics and recent allowlisted event codes in Saved/BugReports/Recovery. At most two complete recovery files per pawn are retained during a session; rotation keeps the last complete snapshot if publication fails. Both are removed on normal pawn teardown. Recovery files can belong to a running game; leftover files alone cannot establish whether a session was interrupted or crashed; termination before the first snapshot may leave nothing. No crash-handler code, crash dumps, automatic uploads or personal file access is involved. Native testing must verify normal teardown, forced termination, directory permissions and file rotation behavior.

### Reviewing reports on Windows
Run `MoonfallUnreal/Build/Get-MoonfallBugReports.ps1` with Windows PowerShell. It prints a local JSON index of up to 100 manual and 100 recovery reports, deduplicates recovery snapshots by session identifier, accepts only expected filenames, schema and kind, skips reparse points and oversized files, and classifies valid timing samples as low throughput, intermittent slow frames or no clear timing issue. It does not infer the crash cause, read unrelated files, modify reports, or upload information. The Windows workflow exercises synthetic reports, not a packaged UE5 game.

Installed-game report discovery checks the standard user-data and package locations, and the NSIS installer's per-user InstallLocation registration. A custom local installation is accepted only if its directory is non-reparse and contains the expected non-reparse MoonfallUnreal.exe. Duplicate report roots are skipped. Unregistered copies may be supplied explicitly with -IncludeInstalled -InstallDirectory; arbitrary Saved directory overrides are not searched. The index remains read-only and bounded.

### ChatGPT diagnostic handoff
In Build Center, select BUG REPORTS, then ASK CHATGPT - PREVIEW REPORT. Review the editable prompt, add reproduction steps, and explicitly copy it into your ChatGPT conversation. Only up to five summaries with fixed classification labels and validated numeric timing fields are included by default. No filenames, local paths, report identifiers or raw logs are copied by the generator. User-added text is their choice. No API key, automatic transmission, embedded AI runtime, or automatic code changes are included. The Windows regression tests verify the prompt bounds and allowlisted data; the interactive clipboard still requires a real desktop test.

The guided AI triage dialog adds nine category choices (including unspecified), severity, reproduction frequency, and one-to-five recent report selection. Optional technical evidence is off by default; enabling it adds validated 1% low FPS, CPU/render/GPU timing estimates, resolution, quality, allowlisted graphics API and reduced-motion setting when available. Arbitrary report strings and invalid numeric fields are excluded. The editable preview remains the final review step before copying. This is a manual ChatGPT handoff, not an embedded AI service.

### Live AI analysis (personal developer workstation)
In Build Center, open BUG REPORTS, ASK CHATGPT - PREVIEW REPORT, and select ANALYZE WITH LIVE AI. Review the exact text, then explicitly approve sending it to OpenAI. Set your own project API key in the local OPENAI_API_KEY environment variable and restart Build Center first. Never embed a shared key, commit credentials or paste a key into a report. API billing is separate from ChatGPT. The Responses API client uses gpt-5.4-mini, store=false, a 16,000-character prompt limit, 2,000 output tokens, a 60-second network timeout and no automatic retry or redirects. Responses are displayed read-only; no commands, repository actions or file writes are executed from AI output. Requests run on a dedicated PowerShell runspace; the manual copy handoff remains available. No actual API request is made by CI. This personal workstation feature does not grant access to ChatGPT conversation history, memory or GitHub, and does not ship a key or service to players. A publicly distributed AI feature would require a secured server-side backend and authenticated users.

### Conversational live AI workspace
After the first response, enter a follow-up question and review the exact outbound text, including a bounded portion of the original report and most recent AI answer. Each request requires explicit approval; a session permits at most ten request attempts. The current report and latest answer remain in memory only, and a failed follow-up keeps the previous successful answer. The latest answer may be copied manually. This is bounded single-step follow-up context rather than complete conversation history; no connection to ChatGPT account memory or repository tools is included. The client rejects prompts containing the configured API key. CI tests context limits and consent without paid requests.
